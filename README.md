# 구름 근무시간

아마란스(`gw.goorm.io`) 근태 API를 직접 호출해 **이번 달 남은 근무시간**을 계산합니다.
하루 8시간제 / 유연근무 최소 6시간 / 월 단위 정산 기준.

두 가지 형태로 제공합니다.

| | 위치 | 세션 |
|---|---|---|
| **Chrome 확장** | [manifest.json](manifest.json), [src/](src/) | 브라우저 쿠키를 읽음 |
| **Android 앱** | [app/](app/) — Capacitor | 앱에서 직접 로그인 |

계산 로직([lib/time.js](src/lib/time.js) · [holidays.js](src/lib/holidays.js) · [calc.js](src/lib/calc.js))은
플랫폼 의존성이 전혀 없어 **양쪽이 같은 파일을 공유**합니다 (`app/sync-lib.sh` 로 복사).

## 배포

- 확장: `./pack-extension.sh` → `amaranth-extension-vX.zip`
- 앱: `cd app && npx cap sync android && (cd android && ./gradlew assembleDebug)` → APK
- GitHub 릴리스에 두 산출물을 올리면, 확장이 [src/lib/updater.js](src/lib/updater.js) 로
  최신 태그와 버전을 비교해 **업데이트 알림**을 띄웁니다.


## 설치

1. `chrome://extensions` → 우측 상단 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램을 로드** → 이 폴더 선택
3. 툴바 아이콘 클릭

`gw.goorm.io`에 로그인만 되어 있으면 **어느 탭에서든** 동작합니다. 근태 페이지를 열어둘 필요가 없습니다.
근태 페이지에 들어가면 패널이 함께 뜹니다. **헤더를 잡고 끌어서 원하는 자리에 둘 수
있고**, 접으면 **작은 버블**로 줄여 남은 시간만 띄울 수 있습니다(설정). 팝업 `설정`
에서 **아예 끌 수도 있고**,
켜 둔다면 **위치를 네 모서리 중 고를 수 있습니다**(기본 우측 하단). 위치는 패널
헤더의 `⤢` 로도 바꿉니다. 어느 쪽에서 바꾸든 열려 있는 탭에 즉시 반영됩니다 —
새로고침이 필요 없습니다.

드래그한 좌표는 모서리 설정보다 우선합니다. 모서리를 다시 고르면 좌표가 지워집니다.
창 크기가 바뀌면 화면 밖으로 나간 패널을 다시 당겨 넣습니다. 몇 픽셀 이내의 움직임은
클릭으로 봅니다 — 안 그러면 접기 버튼을 누르다 흔들려도 위치가 바뀝니다.

패널을 끄면 DOM 에서 지우고 **자동 갱신도 멈춥니다.** 팝업은 열 때마다 따로
조회하므로 백그라운드로 API 를 두드릴 이유가 없습니다 — 근태신청서·결재처럼
`window.open()` 으로 열리는 **별도 팝업 창에는 뜨지 않습니다.**

## 계산 규칙

| 항목 | 정의 |
|---|---|
| 이번 달 인정근무 | `Σ appworkTm` — 마감된 날의 연차·반차 인정분은 서버가 이미 반영 |
| 휴가 인정 (예정) | 아직 집계 전인 오늘·미래 휴가. 반차 = 소정의 절반 |
| 월 소정근로 | **8시간 × 근무일수** |
| **남은 근무시간** | `월 소정근로 − (인정근무 + 휴가 인정)` |
| 남은 근무일 | 오늘 포함, 소정근로시간이 있고 **휴가로 다 덮이지 않은** 남은 날 |
| 하루 필요 | `(남은 근무시간 − 이미 정해진 날의 필요분) ÷ 나머지 근무일` |
| 어제까지 누적 | `Σ(인정근무 + 휴가 인정 − 8시간)` (마감된 날) |

### 하루 기준은 8시간 고정입니다

서버의 `selfCommuteStandardWorkTm` 은 **법정근로시간**이라 8시간보다 짧게 잡히는 날이 있습니다.
그 값을 기준으로 삼으면 실제로 채워야 하는 시간과 어긋나므로, 서버 값은 **"그날이 근무일인가"를
판별하는 데만** 쓰고 시간은 설정값(기본 8시간)으로 고정합니다.

### 필요 시간이 정해진 날은 평균에서 빼고 계산합니다

반차가 걸린 날은 그날 필요분(`8h − 4h = 4h`)이 이미 정해져 있습니다. 이걸 평균에 섞으면
8시간 아래로 끌려 내려가서, 정작 **평범한 날 몇 시간 일해야 하는지**를 알 수 없습니다.
그래서 반차 날과 계획을 넣은 날은 분자·분모에서 빼고 나머지 날로만 평균을 냅니다.

```
남은 125시간 32분, 남은 근무일 17일 (반차 2일 포함)

  섞어서 계산  → 125:32 ÷ 17 = 7시간 23분   ← 평범한 날 기준으로는 틀린 값
  반차 분리    → (125:32 − 8h) ÷ 15 = 7시간 50분   ✓
```

## 근무 계획

툴바 팝업에 달력이 **항상 펼쳐져** 있습니다. 남은 근무일을 눌러 그날 일할 시간을
정해두면, 나머지 날에 하루 몇 시간이 필요한지 즉시 다시 계산됩니다.

팝업 순서는 `남은 근무시간 → 오늘 출퇴근 → 월 집계 → 달력` 입니다.
오늘 정보를 보려고 달력 아래까지 스크롤할 일이 없도록 달력 위에 둡니다.

```
남은 144시간 / 18일

  계획 없음              → 하루 8시간
  9/3 하루만 6시간        → 하루 8시간 7분     (138h ÷ 17일)
  9/3~9/9 다섯 날 6시간   → 하루 8시간 46분    (114h ÷ 13일)
  남은 날 전부 6시간      → 계획 부족 36시간   (18일 × 6h = 108h)
```

달력의 색: 파란 테두리 = 계획, 하늘색 = 휴가, 회색 = 마감(실적), 주황 테두리 = 오늘.

마감된 날 칸에는 **월 집계와 같은 값**이 들어갑니다 — 인정근무에 휴가 크레딧을 더한
값입니다. 칸의 합이 `이번 달 인정근무` 와 정확히 일치합니다.

마감된 날과 휴일은 누를 수 없습니다. 계획은 브라우저에만 저장되고 그룹웨어로 전송되지 않습니다.

유연근무 하루 최소 6시간 기준으로 판정합니다.

- `남은 시간 ≤ 남은 일수 × 6h` → **매일 6시간이면 충족** (초록)
- `6h × 일수 < 남은 시간 ≤ 8h × 일수` → **매일 6시간으론 부족** (주황)
- `남은 시간 > 8h × 일수` → **8시간을 다 채워도 부족** (빨강)

오늘 출근했다면 **언제 퇴근하면 되는지**를 세 기준(최소 6h / 월 페이스 / 정량 8h)으로 보여줍니다.
`출근시각 + 근무시간 + 휴게시간`으로 계산하고, 각 퇴근 시각 옆에 **더 일해야 하는 시간**을
괄호로 붙입니다 — `18:00 (5시간 남음)`, 이미 지났으면 `(충족)`.



**경과도 남은 시간도 벽시계가 아니라 실제 일하는 시간입니다.** 점심 휴게(12:00~13:00
고정)와 겹치는 만큼을 양쪽에서 뺍니다. 그래서 **경과 + 남은 = 오늘 필요 시간**이
항상 맞습니다.

| 09:00 출근 · 정량 8시간 | 경과 | 남은 | 합 |
|---|---|---|---|
| 11:30 | 2시간 30분 | 5시간 30분 | 8시간 |
| 12:30 | 3시간 | 5시간 | 8시간 |
| 14:00 | 4시간 | 4시간 | 8시간 |

**휴가 구간이 휴게를 이미 흡수한 날은 빼지 않습니다.** 오전반차 후 09:00~13:00 은
쭉 일하므로 뺄 휴게가 없습니다.

**휴가를 쓴 날은 유연근무 하한(6시간)이 적용되지 않습니다.** 그날 남은 소정근로가 곧 최소
근무시간입니다 — 오전반차(4시간 인정)면 최소도 정량도 `8h − 4h = 4h` 하나로 합쳐 보여줍니다.

**휴게시간은 하루에 한 번만 적용됩니다.** 오전반차 `09:00~14:00` 처럼 휴가 구간이 이미
휴게를 흡수했다면, 남은 근무에는 또 더하지 않습니다. 이건 60분 기본 휴게 이야기이고,
**휴게·외출 신청은 다루지 않습니다** (아래 참고).

| 상황 | 출근 | 퇴근 |
|---|---|---|
| 오전반차 `09:00~14:00` | 14:39 | `14:39 + 4h` = **18:39** (휴게 추가 없음) |
| 오후반차 `14:00~18:00` | 09:00 | `09:00 + 1h + 4h` = **14:00** |
| 휴가 없음 | 10:00 | `10:00 + 1h + 8h` = **19:00** |
| 시간연차 `16:00~18:00` | 09:00 | `09:00 + 1h + 6h` = **16:00** |

### 검증

2026년 8월 실제 데이터로 대조했습니다.

```
8월 소정근로  160시간 (20일)
8월 인정근무  164시간 55분
8/31 제외 누적  +4시간 38분   ← 그룹웨어 화면의 "8월 누적 04시간 38분초과달성"과 일치
```

## API

네 엔드포인트를 씁니다.

### 1. 월 근태 조회

```
POST https://gw.goorm.io/personal/hpd0210/getWorkTimeList
  Authorization : Bearer <cookie.oAuthToken>
  transaction-id: 32자리 랜덤 hex
  timestamp     : Math.floor(Date.now()/1000)
  Access-Domain : https://gw.goorm.io
  menu-code     : HPD0210
  wehago-sign   : Base64( HmacSHA256(token + tid + timestamp + pathname, cookie.signKey) )
                  ※ pathname 만 서명한다 (쿼리스트링 제외)

  {"atDtList": ["20260901", "20260902", ...]}
```

- WEHAGO(더존 Amaranth 10) 플랫폼의 서명 요청 방식입니다. 구현은 [src/lib/gwapi.js](src/lib/gwapi.js).
- 토큰(`oAuthToken`)과 서명키(`signKey`)는 쿠키에 있습니다 (HttpOnly 아님).
- `coCd` / `empCd` 는 **보내지 않아도 됩니다** — 서버가 토큰에서 판별합니다.
- `atDtList` 에 원하는 날짜를 나열하면 되므로 **월 전체를 한 번에** 가져옵니다.

주요 응답 필드:

| 필드 | 의미 |
|---|---|
| `appworkTotalTm` | **인정근무 (분). 우리가 쓰는 값.** 회사가 얹어 주는 시간까지 포함 |
| `appworkTm` | 인정근무 (분). 얹어 준 시간이 **빠져 있다** |
| `outgoworkTm` | 외출근무 = 자율휴게 신청분 (분) |
| `selfCommuteStandardWorkTm` | 그날의 소정근로시간 (분). 휴일이면 0 |
| `exceptworkTm` | 제외근무 = 휴게시간 (보통 60) |
| `comeTm` / `leaveTm` | 실제 출퇴근 타각 (`HHMM`, 없으면 `----`) |
| `appcomeTm` / `appleaveTm` | 인정 출퇴근 |
| `attresultNm` | 정상근무 / 휴일 / 지각 / 부족 / 이상근태 |
| `atNm` | 오전반차 등 휴가 종류 |
| `worktmNm` | 승인 / 대기 |
| `holiYn` | 공휴일 여부 |
| `coCd` / `empCd` | 회사·사원 코드 (아래 실시간 조회에 필요) |

#### 인정근무는 `appworkTotalTm` 을 씁니다

회사가 근무시간을 얹어 주는 경우(스마트데이 등)가 있습니다. 그 시간은
`appworkTm` 에 안 들어가고 `appworkTotalTm` 에만 들어옵니다.

```
2026-09-11 (스마데)  appworkTm 417 · appworkTotalTm 537   ← 120분 차이
그 외의 날            둘이 같다 (578/578 · 485/485 · 530/530 · 497/497)
```

`appworkTotalTm` 이 체류시간이 아니라는 것도 확인했습니다 — 2026-09-01 은
체류가 698분(09:00~20:38)인데 두 필드 모두 578 입니다. 즉 체류가 아니라
"인정근무 + 얹어 준 시간" 입니다.

반차·휴가 인정분은 `appcomeTm` 이 앞당겨지는 방식이라 양쪽에 이미 들어 있습니다
(9/1 오전반차 → `comeTm` 14:39 이지만 `appcomeTm` 09:00).

**API 에 월 합계는 없습니다.** `getWorkTimeList` 는 평평한 배열만 돌려주고,
개인근무시간현황 화면이 행을 더해서 보여줍니다. 그래서 "화면 총합을 그대로
가져오기" 는 불가능하고, 같은 필드를 더하는 것이 곧 같은 값입니다.
어느 필드인지 대조하는 도구가 [tools/capture-worktime.js](tools/capture-worktime.js)
의 `__dumpMonth()` 입니다.

### 2. 근태신청(휴가) 조회

```
POST https://gw.goorm.io/personal/hpd0120/0hp00001
  menu-code: HPD0120
  {"startDt": "20260901", "endDt": "20260930", "flag": "2"}

  → resultData.atPopUpDetailInfos[].attendApplications[]
     { startDt, endDt, startTm, endTm, atItemNm: "연차휴가", atNm: "오전반차(보상)",
       approStateNm: "결재진행", ... }
```

- **`flag` 가 조회 기준을 정합니다** — `"1"` = 신청일, `"2"` = 사용일(휴가일).
  `flag=1` 로 9월을 조회하면 *9월에 신청한* 8월 휴가가 딸려 옵니다. **`flag=2` 를 씁니다.**
- `coCd` 는 생략 가능합니다.
- `결재진행`(승인 대기)도 포함하고, 반려·취소·취하 건은 제외합니다.
- 이름으로 종류를 가릅니다 — `휴게|외출` → 휴게, `휴가|연차|반차|…` → 휴가, 나머지(출장·시간외)는 다루지 않습니다.

**신청 구간에는 휴게시간이 포함돼 있습니다.** 오전반차는 점심을 물고 있어 구간이 5시간
(`09:00~14:00`)인데 오후반차는 4시간(`14:00~18:00`)입니다. 둘 다 실제 휴가는 4시간입니다.

그래서 **구간이 4시간을 넘으면 휴게 1시간을 뺍니다.**

| 신청 구간 | 길이 | 인정 |
|---|---|---|
| `07:30~12:30` 오전반차 | 5시간 | 4시간 |
| `14:00~18:00` 오후반차 | 4시간 | 4시간 |
| `09:00~18:00` 종일연차 | 9시간 | 8시간 |
| `16:00~18:00` 시간연차 | 2시간 | 2시간 |

`startTm`/`endTm` 이 없으면 `atNm` 이름으로 추정합니다 (반반차 = 1/4, 반차 = 1/2, 그 외 = 하루치).
하루에 오전반차 + 오후반차가 겹치면 합산하되 그날 소정근로를 넘지 않게 자릅니다.

### 휴게·외출 신청 — 다루지 않습니다

같은 엔드포인트의 **`atPopupCd 51`** 그룹으로 함께 내려오지만 계산에 넣지 않습니다.
결재가 끝나면 서버가 알아서 인정근무시간(`appworkTm`)에 반영하기 때문에, 결재 전
신청분을 미리 빼 봐야 이중 보정만 됩니다.

## 배치 지연과 하이브리드 추정

집계된 근태 데이터는 **다음날 새벽 5시 배치**로 채워집니다 (8/31 행의 `insertDt` = `2026-09-01 05:00:09 SYSTEM`).
그래서 오늘과 미래 날짜는 `selfCommuteStandardWorkTm` 이 `0`으로 옵니다.
(오늘 출퇴근 타각 자체는 위 실시간 엔드포인트로 바로 읽을 수 있습니다.)

진행 중인 달의 소정근로시간을 알 수 없으면 "남은 시간"을 계산할 수 없으므로 다음과 같이 처리합니다.

- **마감된 날** → 서버 값을 그대로 사용
- **오늘·미래** → **회사 휴일 목록**(아래)으로 근무일을 판별해 소정근로를 추정.
  서버 목록이 없거나 빈약하면 [src/lib/holidays.js](src/lib/holidays.js) 의 내장 표로 폴백

## 결재진행 중인 휴가

서버 배치는 **결재가 완료된** 휴가만 반영합니다. 결재진행 중이면 마감된 날이어도
반차가 빠진 순수 타각 시간만 들어옵니다.

```
9/1 오전반차(결재진행) → appworkTm 388분 (14:39~21:07)
   휴게 차감도, 반차 4시간 인정도 없이 타각 그대로.
   그대로 두면 누적이 388 − 480 = −1시간 32분 으로 찍힌다 (실제로는 +2시간 28분).
```

그래서 휴가 크레딧을 더할지는 "마감 여부"가 아니라 **서버가 그 휴가를 반영했는지**로
판단합니다 — 행의 `atNm` 에 휴가명이 찍혀 있으면 이미 반영된 것이므로 더하지 않습니다.
결재가 완료되면 서버 값으로 넘어가면서 같은 결과가 나옵니다 (이중 계상 없음).

추정한 날짜 수는 화면에 표시되고, 달이 진행되면서 서버 값으로 자동 교정됩니다.
회사 휴무일이 표와 다르면 팝업 **설정 → 추가 휴무일 / 휴일 해제**에서 조정하세요.

### 대체공휴일 규칙 (표를 고칠 때 확인)

| 대상 | 대체 조건 |
|---|---|
| 3·1절, 광복절, 개천절, 한글날, 부처님오신날, 성탄절 | 토·일 겹침 |
| 어린이날 | 토·일 또는 다른 공휴일 겹침 |
| 설날·추석 연휴 | 일요일 또는 다른 공휴일 겹침 — **토요일은 대체 없음** |
| 신정, 현충일 | 대체 없음 |

흔히 틀리는 두 가지입니다.

- 추석·설 연휴가 **토요일**과 겹쳐도 대체휴일은 생기지 않습니다.
  2026 추석은 9/24(목)~9/26(토)이고 **9/28(월)은 평일**입니다.
- **현충일**은 어느 요일에 걸려도 대체휴일이 없습니다.

**근태신청서 화면까지 엽니다.** 신청·상신은 그 화면에서 직접 합니다.

| | |
|---|---|
| 확장 팝업 | **휴가 신청** → `#/HP/HPD0110/HPD0110` |
| 앱 | 상단 **＋** → 세션을 쿠키로 심고 같은 화면으로 이동 |

### 결재 팝업으로 바로 갈 수 없는 이유

연차 신청 팝업 주소는 이렇게 생겼습니다.

```
/#/popup?MicroModuleCode=eap&callComp=UBAP001&formId=249
        &approkey=ERP_<uuid>&popupUUID=<uuid>&…
```

두 번 시도했고 둘 다 실패했습니다.

1. **approkey 를 새로 만들어 열기** → `연동본문 데이터 조회 실패`
2. **API 로 초안(0hr00011 + create)을 먼저 만들고 열기** → 같은 실패

이유는 `approkey` 가 **서버에 등록되는 값이 아니기 때문**입니다. 실제 흐름에서
팝업 직전에 호출되는 `eap096A45`·`eap096A48` 어느 쪽도 approkey 를 보내지 않습니다.
즉 approkey 는 **같은 탭 SPA 의 메모리 상태**를 가리키는 키이고, 근태신청서 화면이
그 상태를 만들어 둡니다. URL 로 냉시작하면 그 상태가 없어 연동이 본문을 못 찾습니다.

```
연동프로세스코드 : HP_HPD0110_00011
{"resultCode":-1,"resultMessage":"Internal Server Error"}
```

### API 로 어디까지 되는지 (기록)

`calculateApplicationDays`(계산) → `validateNew`(검증) → `0hr00011`(근태신청 저장)
→ `create`(결재문서 생성)까지는 **전부 동작합니다.** `approLineId` 를 비우면 서버가
기본 결재선을 붙여 줍니다. 페이로드도 실제 요청과 전 필드 일치를 확인했습니다
(`timeCd 7730`, `workTp 1`, `appDyFg D`, atCd 는 종일 1101·1105 / 오전 1102·1106 /
오후 1103·1107, `linkAtCd 1010`).

문제는 `create` 결과가 `approState "2"`(미상신 초안)이라는 점입니다. 결재선에 올리는
마지막 단계를 찾지 못했고, 절반만 재현하면 초안만 쌓입니다. 그래서 쓰지 않습니다.

## 자동 갱신

화면에서 가장 빨리 낡는 값(경과 시간·퇴근 시각)은 `new Date()` 로 계산되므로 **서버와 무관**합니다.
반대로 월 집계는 다음날 새벽 배치라 낮에 아무리 불러도 값이 그대로입니다.
그래서 "N분마다 전부 다시 조회"는 **가장 낡는 값은 그대로 두고 서버만 두드리는** 방식이 됩니다.

둘로 나눴습니다.

| 무엇 | 주기 | 서버 호출 |
|---|---|---|
| 화면 다시 그리기 (경과 시간·퇴근 시각) | 30초 | **없음** |
| 오늘 타각 | 5분 — **퇴근이 찍히면 중단** | 1건 |
| 월 근태 + 휴가 | 부팅 시 1회 | 30일치 |

월 집계를 다시 부르는 경우는 세 가지뿐입니다 — **자정을 넘겼을 때**, **10분 넘게 자리를
비웠다 돌아왔을 때**, 그리고 수동 새로고침.

**탭이 보이지 않으면 아무것도 하지 않습니다** (`document.hidden`). 다른 탭에서 일하는 동안에는
폴링이 완전히 멈추고, 돌아오면 그때 판단합니다.

### 실패 처리

- **세션 만료**(401/403) → 자동 갱신을 **중단**하고 상태줄에 사유를 띄웁니다.
  만료된 세션으로 계속 두드려봐야 소용없기 때문입니다. 새로고침을 누르면 재개합니다.
- **그 외 오류** → 1 → 2 → 4 → 8 → 16 → 30분으로 백오프하고, 한 번 성공하면 초기화합니다.
  남은 대기 시간은 상태줄에 표시됩니다.

팝업은 열 때마다 새로 조회하므로 자동 재조회가 없습니다. 열어둔 동안 경과 시간이 낡지 않도록
30초마다 다시 그리기만 합니다.

## 근태 이상 (인정근무 0)

출근 타각이 빠지면 아마란스가 `attresultNm: "이상근태"` 로 분류하고 **인정근무를 0으로** 줍니다.
실제로 몇 시간을 일했든 상관없습니다.

```
20260812  이상근태  comeTm=----  leaveTm=2101  appworkTm=0  std=480
```

그대로 두면 그날 8시간이 통째로 부족분에 빨려 들어갑니다. 확장이 계산으로 메울 수 있는 값이
아니라(근태조정을 신청해야 채워집니다) **경고로 띄웁니다** — 해당 날짜와 타각 시각,
출퇴근 타각이 둘 다 있으면 못 받은 시간까지 함께 보여줍니다.

## 왜 휴가 신청은 안 만들었나

확장은 **전부 읽기 전용**입니다. 휴가 신청 기능은 의도적으로 넣지 않았습니다.

- 신청 API 를 알아내려면 **실제 신청서를 상신**해야 합니다. 결재자에게 알림이 가고
  되돌리려면 취소 절차를 밟아야 하는, 부작용이 되돌리기 어려운 캡처입니다.
- 신청서에는 결재선·사유·대결자 등 필드가 많고 검증이 서버와 화면에 흩어져 있어,
  일부만 흉내내면 **잘못된 문서가 결재에 올라갈** 위험이 있습니다.
- 지금은 읽기만 하므로 확장이 오작동해도 인사 데이터가 바뀌지 않습니다.
  쓰기가 들어가는 순간 그 보장이 사라집니다.

대신 **화면으로 이동하는 버튼**을 넣었습니다. 화면 코드는 메뉴 권한 조회(`/gw/gw999A12`)로
확인했습니다.

| 버튼 | 화면 | 경로 |
|---|---|---|
| 휴가 신청 | 부서 근태일정 | `#/HP/HPD0110/HPD0110` |
| 신청 현황 | 개인근태신청현황 | `#/HP/HPD0120/HPD0120` |
| 근무시간 | 개인근무시간현황 | `#/HP/HPD0210/HPD0210` |

팝업에서 누르면 이미 열려 있는 `gw.goorm.io` 탭을 재사용하고, 없으면 새 탭을 엽니다.
페이지 안 패널에서는 해시만 바꿔 같은 탭에서 이동합니다.

### 휴가 신청

신청서 화면을 열지 않고 **API 로 초안을 만든 뒤 결재 화면을 새 탭으로 엽니다.**
상신은 그 화면에서 사용자가 직접 누릅니다.

```
calculateApplicationDays   일수·인정시간·연차차감을 서버가 계산 (읽기)
validateNew                중복·잔여연차 검증 (읽기)
        ↓ 확인 화면
0hr00011                   신청 확정. 응답이 곧 결재문서 제목이다
create                     초안 생성 → appSq / appDt / coCd, approState "2"
GetLinkKey                 approKey 를 등록하고 linkKey 를 받는다
SetEnageGroup              approKey 에 양식·제목·본문조회API 를 붙인다
saveLinkKey                linkKey 를 방금 만든 초안(appSq)에 묶는다
/#popup?…&approkey=…       결재 화면. 여기서 결재상신
```

**`approkey` 등록이 전부입니다.** `ERP_<uuid>` 는 클라이언트가 만드는 난수지만
**그냥 만들어 쓰는 값이 아니라 서버에 등록해야 하는 값**입니다.

```
POST /system/apiUtilEap/GetLinkKey
  { menuCode: "HPD0110", approKey: "ERP_<uuid>", vPCoCd: coCd, coCd }
→ { approKey, linkKey: "1000_HPD0110_20260907_2023030702_0008" }

POST /system/apiUtilEap/SetEnageGroup
  { approKey, linkKey, formDTp: "HP_HPD0110_00011", formId: "249",
    formNm: "연차휴가신청서", docTitle,
    contentsApi: "/human/attendapplication/interlock/getInterlockFormContents",
    statusApi:   "/human/attendapplication/interlock/setInterlockSync",
    contents: "", dummy1: "", link: "", vPCoCd: coCd, coCd }

POST /human/openapi/attendapplication/saveLinkKey
  { linkKey, appSq, coCd, appDt }
```

> `연동본문 데이터 조회 실패 / HP_HPD0110_00011` 은 이 세 단계를 빠뜨렸을 때 나옵니다.
> 서버에 등록된 적 없는 approkey 로 본문을 찾으니 당연히 없습니다.
>
> 가설 두 개를 먼저 틀렸습니다 — `create` 의 `linkKey` 에 실어 보내는 것도 아니고
> (실제 요청도 `""` 입니다), `create` 응답에 실려 오는 것도 아니고
> (`linkKey: ""`, `calLinkKey: "20260902.1"`), 스토리지로 넘기는 것도 아닙니다
> (`ERP_` 키가 local·session 어디에도 없습니다). 네트워크 타임라인을 찍어
> `create` 와 `window.open` 사이를 보고서야 등록 단계 셋이 드러났습니다.

`approState:"2"` 는 정상입니다 — 초안 상태이고 상신은 결재 화면에서 일어납니다.
(미상신 초안은 개인근태신청현황에 뜨지 않으니 목록 조회로 성공 판정을 하면 안 됩니다)

제목은 `0hr00011` 응답을 그대로 씁니다 — 화면도 그렇게 합니다.
`[SRE팀 오세준]  09-11 (15:00~19:00)(1.0일)오후반차신청서`

| 종류 | atCd | 구간 |
|---|---|---|
| 연차 | `1101` | `09:00~18:00` |
| 오전반차 | `1102` | `09:00~14:00` |
| 오후반차 | `1103` | `15:00~19:00` |
| 연차(보상) | `1105` | `09:00~18:00` |
| 오전반차(보상) | `1106` | `09:00~14:00` |
| 오후반차(보상) | `1107` | `15:00~19:00` |

점심을 물고 있는 구간에는 휴게 1시간이 끼어 있습니다 — 종류가 정하므로 고르지 않습니다.
시작시각만 바꿀 수 있습니다.

흐름을 다시 확인해야 하면 [tools/capture.js](tools/capture.js) 를 gw 콘솔에 붙여
실행한 뒤 실제 신청을 하고 `__capDump()` 를 부르면 됩니다. 결재 팝업 안의 요청까지
같이 잡힙니다.

**앱도 같은 코드를 씁니다.** `lib/leave.js` 와 `lib/break.js` 는
[app/sync-lib.sh](app/sync-lib.sh) 로 복사되고, 앱의 `GW.api.call` 이 확장과 같은 계약(`resultData` 반환)이라 그대로 돕니다.
다른 건 결재 화면을 여는 방법뿐입니다 — 확장은 새 탭, 앱은 WebView 를 gw.goorm.io 로
이동시킵니다. iframe 은 앱 출처(localhost)에 대해 서드파티라 안드로이드가 쿠키를
막지만, 1st-party 이동이면 정상 적용됩니다.

## 웹앱은 불가능하다 (시도했다가 접음)

`app/www` 를 정적 호스팅해 아이폰에서도 쓰려고 했다. 접었다. 이유를 남긴다.

**CORS 는 열려 있다.** `gw.goorm.io` 는 `Origin` 을 그대로 반사하고
`Access-Control-Allow-Credentials: true` 를 준다. 그래서 자체 로그인으로 API 를
부르는 것 자체는 웹에서도 된다.

**막히는 건 두 가지다.**

**① 브라우저의 gw 세션으로 API 를 부를 수 없다** — 익스텐션 방식이 웹에서 안 되는 이유.

```
쿠키만      → 601 "허용된 쿠키 인증 URL이 아닙니다"
서명+쿠키   → 107 "GetToken 요청 시, 비인증 URL을 레디스에서 찾을 수 없습니다"
```

`/human/*` 는 `wehago-sign`(사용자 `signKey` 로 만드는 HMAC)을 요구하는데,
`signKey` 는 **HttpOnly 쿠키**라 웹 페이지에서 읽을 수 없다. 익스텐션은
`chrome.cookies` 로 HttpOnly 를 읽을 수 있어서 가능한 것이다.

**② 결재 화면에 세션을 넘길 수 없다.**

`loginType=set-cookie` 는 세션을 만드는 게 아니라 **검증 없이 쿠키를 써주는 헬퍼**다
— 더미 토큰(`oAuthToken=DUMMY`)을 보내도 그대로 `Set-Cookie` 로 내려준다.
브라우저는 그 쿠키를 `gw.goorm.io` 호스트 쿠키로 정상 저장한다(헤드리스 크롬의
쿠키 DB 로 확인). 그런데 우리 로그인 토큰은 **gw 웹 세션으로는 인정되지 않아**
결재 화면이 로그인을 요구한다. 게다가 이걸 부르면 사용자가 gw 에 직접 로그인해
만든 멀쩡한 세션 쿠키를 덮어써서 오히려 로그아웃시킨다.

**결론:** 웹앱은 자체 로그인(API용) + gw 로그인(결재 화면용)으로 **로그인이 두 번**
강제되고, 그마저 결재 화면 세션 이관이 되지 않는다. 아이폰은 익스텐션도 앱도 쓸 수
없으니, 지원하려면 Capacitor iOS 빌드가 유일한 길이다(유료 개발자 계정 필요).

### 자율휴게 신청

`휴게 신청` 은 같은 흐름을 씁니다. 실제 신청을 캡처해 재현했고, 휴가와 다른 점은 셋뿐입니다.

| | 연차휴가 | 자율휴게 |
|---|---|---|
| `atCd` / `linkAtCd` | `1101`~`1107` / `1010` | `5201` / `5110` |
| 결재 양식 | `249` / `HP_HPD0110_00011` | `151` / `HP_HPD0110_00052` |
| `validateNew` | 호출함 | **호출하지 않음** (화면도 안 부름) |
| `ycUseCnt` | 0.5 / 1.0 | **0** (연차를 쓰지 않음) |
| `appRmkDc` | 빈 문자열 | **사유** (예: `운동`) |

```
calculateApplicationDays → 0hr00011 → create
  → GetLinkKey → SetEnageGroup → saveLinkKey → 결재 화면
```

**최대 1시간**입니다 — 양식 설명이 "점심시간 외 개인용무로 인하여 최대 1시간까지
추가 휴게신청"입니다. 시작 시각과 길이(30분/1시간), 사유를 받습니다.

휴게는 근로시간에서 **빠지므로** 퇴근이 그만큼 밀립니다. 다만 확장의 계산에는 넣지
않습니다 — 결재가 끝나면 서버가 인정근무시간에 반영합니다 (위 참고).

## 그날 근태 (누가 휴가인지)

달력 날짜를 누르면 **그날 창**이 뜹니다 — 근무 계획 편집과 자리를 비우는 사람이
한 곳에 있습니다. `우리 팀` / `전체` 를 고를 수 있고, 휴가 → 출장 → 외근 순으로
묶어 보여줍니다.

**지난 날과 휴일도 누를 수 있습니다.** 계획을 세울 수는 없지만 그날 누가 쉬었는지는
볼 수 있어야 하므로, 계획 편집 줄만 숨깁니다.

```
POST /schres/sc111A03    (일정 모듈의 근태캘린더)
  { companyInfo: { compSeq, groupSeq, deptSeq, emailAddr, emailDomain },
    startDate, endDate, acalList: ["1"], … }
→ resultList[] : partName · createDeptName · atNm · atCd · startDate · endDate · alldayYn
```

**화면이 날짜마다 한 번씩 부르므로 우리도 하루씩 부릅니다.** 본문에 `startDate`/
`endDate` 가 있어 범위가 될 수도 있지만 확인된 바 없습니다. 날짜별로 한 번 받아
두고 `우리 팀`/`전체` 전환은 클라이언트에서 거릅니다.

종류는 `atCd` 앞자리로 갈립니다 — `1xxx` 휴가, `2xxx` 출장, `3xxx` 외근.

### WEHAGO 식별자

이 API 는 본문에 `groupSeq`·`compSeq`·`deptSeq`·이메일을 요구합니다. 근태 API 가
쓰는 ERP 코드(`empCd`/`coCd`)와는 **다른 체계**라 따로 구해야 합니다.

`gw.goorm.io` 의 `sessionStorage.userInfo` 에 들어 있고, 콘텐츠 스크립트가 같은
출처라 읽을 수 있습니다(격리 세계라도 스토리지는 공유됩니다). 팝업은 다른 출처라
못 읽으므로 콘텐츠 스크립트가 캐시해 둡니다. **그래서 `gw.goorm.io` 탭을 한 번은
열어야** 이 기능이 동작합니다.

## 팀 근무시간 공유

팀원이 언제 퇴근하는지 볼 방법이 그룹웨어에 없습니다. 각자 계산한 결과를
`worktime.goorm.io` 한 곳에 모읍니다.

**그룹웨어의 부서가 그대로 팀입니다.** 만들기도 참여도 링크도 열쇠도 없고,
**고를 수 있는 것도 없습니다** — 팀도 이름도 그룹웨어가 알려 주는 값으로 고정합니다.
화면은 확인용이고, `[시작]` 하나만 누르면 됩니다.

    teamId  = SHA-256("worktime-team-v2:" + compSeq + ":" + deptSeq)    앞 16자
    joinKey = SHA-256("worktime-join-v2:" + compSeq + ":" + deptSeq)    앞 32자

부서명이 아니라 `deptSeq` 로 만듭니다. 부서명은 회사마다 겹칠 수 있고("개발팀")
이름이 바뀌면 팀이 갈라집니다. `compSeq` 를 앞에 붙여 회사끼리도 겹치지 않게 합니다.
부서명은 화면에 보여 줄 때만 쓰고, 이름이 바뀌면 따라갑니다(주소는 그대로).

### 열쇠 대신 "고를 수 없게" 로 막습니다

열쇠를 하나 두면 팀원마다 그걸 받아 넣어야 하고, 그 번거로움이 기능을 안 쓰게
만듭니다. 그렇다고 팀 이름을 입력칸으로 열어 두면 아무 팀이나 적어 넣고 남의
부서를 들여다볼 수 있습니다.

그래서 **입력 자체를 없앴습니다.** 클라이언트가 계산하는 주소는 자기 부서 하나뿐이고,
다른 부서를 지목할 경로가 UI 에도 저장값에도 없습니다.

예외는 하나입니다. 그룹웨어 응답에서 **이름을 못 읽었을 때만** 표시 이름을 직접
넣게 합니다(응답 구조가 버전마다 다릅니다). **팀은 어떤 경우에도 고칠 수 없습니다.**

**주소 자체가 비밀은 아닙니다.** 계산식이 이 저장소에 공개돼 있고 `deptSeq` 는 작은
정수라, 확장을 거치지 않고 API 를 직접 부르는 사람은 값을 맞춰 볼 수 있습니다.
`joinKey` 는 서버 형식을 맞추는 값일 뿐 보호 수단이 아닙니다. 거기까지 막으려면
API 를 `internal-private` ALB 로 옮기거나(집·아이폰에서 못 씀), 회사 SSO 를 앞단에
붙이거나, 서버가 그룹웨어 세션을 검증해야 합니다. 지금은 넣지 않았습니다.

**공유를 원하지 않으면 체크박스를 끄면 됩니다.** 끄면 올려 둔 기록도 지웁니다.
켜지 않으면 아무것도 올라가지 않습니다.

### 자기 칸은 자기만 고칩니다

이건 실제로 동작합니다. `selfId`(자리)와 `writeKey`(그 자리의 열쇠)를 브라우저에서
한 번 만들어 계속 씁니다. `writeKey` 가 다르면 남의 칸을 덮어쓸 수 없고,
서버는 응답에서 `writeKey` 를 빼고 줍니다.

같은 사람이 확장과 웹앱을 같이 쓰면 자리가 둘로 보입니다. 합치려면 계정이 필요한데,
계정을 두지 않기로 했으므로 그대로 둡니다.

### 올라가는 값

[team.js 의 `summarize`](src/lib/team.js) 가 고르는 것이 전부입니다.

    name, dept, inAt, outAt, workedMin, leftMin, monthLeftMin, leaveNm

서버도 같은 목록만 화이트리스트로 받고 나머지는 버립니다([`sanitize`](server/index.js)).
**그룹웨어 토큰·쿠키는 공유 서버로 가지 않습니다.** 근태 원본도 올리지 않습니다 —
계산은 각자 기기에서 끝내고 결과만 보냅니다.

퇴근 시각은 **정량(소정근로) 기준**을 공유합니다. 유연근무 최소 6시간은 각자 사정이라
남이 볼 값으로 맞지 않습니다.

### API

    PUT    /api/teams/:id                  { joinKey, name }   있으면 확인, 없으면 생성
    GET    /api/teams/:id?k=<joinKey>                        → { name, members[] }
    PUT    /api/teams/:id/me?k=<joinKey>   { …요약 }
    DELETE /api/teams/:id/me?k=<joinKey>

무작위로 팀을 만들어 주던 `POST /api/teams` 는 없앴습니다. 팀이 전부 이름에서
파생되므로 쓰이지 않는데, 인터넷에 열려 있으면 아무나 팀 한도를 채울 수 있습니다.

- 열쇠 비교는 `crypto.timingSafeEqual` 로 합니다.
- 틀린 `joinKey` 는 IP 당 시간당 30회까지만 받고 그 뒤로는 429 입니다. **실패할 때만
  셉니다** — 차단된 IP 에서도 올바른 값은 통과하므로 공용 IP 를 쓰는 사무실에서
  자기 팀이 막히지 않습니다.

### 저장과 정리

파일 하나([server/store.js](server/store.js))입니다. 팀 몇 개에 사람 수십 명,
1인당 몇백 바이트라 DB 를 세울 이유가 없습니다. 그래서 레플리카는 **1개**입니다 —
두 벌이 같은 파일을 들면 나중에 쓴 쪽이 이깁니다.

- 사흘 지난 게시물은 조회할 때 걸러지고 지워집니다.
- 빈 채로 사흘이 지난 팀은 시간마다 도는 정리에서 삭제됩니다.

### 언제 올라가나

| 위치 | 주기 |
|---|---|
| gw.goorm.io 패널 | 5분마다 (상주하므로 이게 주력) |
| 툴바 팝업 | 열 때 + 2분 간격 |
| 웹앱 | 팀 화면을 열 때 |

팝업만으로는 대부분의 시간 동안 남이 보는 값이 낡습니다. 그래서 패널이 올립니다.
어제 올린 값이 오늘 퇴근 시각처럼 보이면 안 되므로, 날짜가 다르면 목록에서
"오늘 기록 없음" 으로 접습니다.

### 호스트 권한을 추가하지 않은 이유

확장이 `worktime.goorm.io` 를 부르지만 `host_permissions` 에 넣지 않았습니다.
공유 API 가 Origin 을 반영해 CORS 를 허용하므로 권한 없이도 됩니다
(`chrome-extension://…` 오리진으로 확인). 권한이 늘면 크롬이 업데이트 후
확장을 비활성화하고 사용자에게 재승인을 요구하는데, 그 대가가 더 큽니다.

## 업데이트 확인

팝업과 페이지 패널에 새 버전 안내가 뜹니다. **자동 설치는 안 됩니다** — 압축해제
로드 방식이라 Chrome 이 대신 갱신해 줄 수 없고, 릴리스 페이지 링크만 띄웁니다.

```
GET https://raw.githubusercontent.com/goorm-dev/sre-amaranth-extension/main/latest.json
→ { "version": "1.3.1", "url": "…/releases/latest" }
```

GitHub API 가 아니라 raw 파일을 씁니다. API 는 인증 없이 **시간당 60회/IP** 제한이
걸리고, raw 는 사실상 없습니다. raw 응답에 `Access-Control-Allow-Origin: *` 이 있어
`host_permissions` 를 늘리지 않아도 됩니다 — 권한 재승인 프롬프트가 뜨지 않습니다.

**20분마다 확인합니다.** 확장을 쓸 때(팝업을 열거나 `gw.goorm.io` 페이지가 뜰 때)만
확인하고, 마지막 확인이 20분 이내면 캐시를 씁니다. 백그라운드 타이머는 없습니다.

캐시는 **확장 버전이 바뀌면 무효**가 됩니다. 안 그러면 방금 올린 버전이 TTL 동안
"새 버전 있음" 으로 남습니다.

팝업의 `새로고침` 은 TTL 을 무시하고 **즉시 확인**합니다.

> 처음엔 TTL 이 6시간이었는데, 릴리스 직후 반나절 가까이 아무에게도 안 뜨는 일이
> 있었습니다. `latest.json` 은 95바이트고 raw 는 rate limit 이 사실상 없어서
> 짧게 잡는 게 맞습니다.

무시한 버전은 다시 띄우지 않습니다.

### 릴리스 규칙

**태그 = `manifest.json` 의 버전**이고, 기본은 **패치 올림**입니다. 마이너는 성격이
다른 기능이 들어갈 때만 올립니다. 사용자가 안내에서 보는 숫자와 릴리스
페이지의 숫자를 같게 두기 위한 것입니다.

버전을 올려 커밋한 뒤 [release.sh](release.sh) 하나로 끝냅니다.

```
sh release.sh "팀 근무시간 공유"            # 커밋 본문을 릴리스 노트로
sh release.sh "팀 근무시간 공유" notes.md   # 따로 쓴 노트로
```

검사 → 패키징 → `git push` → 태그 → `gh release create` 를 한 번에 합니다.
main 이 아니거나, 커밋 안 된 변경이 있거나, 태그·릴리스가 이미 있으면 멈춥니다.

**푸시와 릴리스를 묶은 이유**: 손으로 하다가 한 번 빠뜨렸습니다. `latest.json` 은
1.7.5 인데 릴리스가 없어서, 확장은 "새 버전 있음" 만 띄우고 받을 게 없었습니다.

`latest.json` 을 안 올리면 반대로 **아무에게도 안내가 안 뜹니다.** 릴리스 태그가
아니라 이 파일 하나만 보기 때문입니다. 눈으로는 안 잡혀서 검사에 넣었습니다.

**앱만 바뀐 경우**엔 새 태그를 만들지 않고 기존 릴리스에 APK 만 교체합니다
(`gh release upload <tag> <apk> --clobber`). 확장 사용자에게 알릴 변경이 아니므로
버전을 올리지 않는 게 맞습니다.

## 알려진 한계

- 진행 중인 달의 소정근로시간은 공휴일 표 기반 **추정**입니다 (위 참고).
- 내장 공휴일 표는 서버 목록이 빈약한 해에만 쓰이는 폴백입니다 (2025–2027년, 수작업).
  대체공휴일 규칙은 위 표를 참고하세요.
- 휴게시간은 60분 고정으로 계산합니다. 서버는 근무시간에 따라 더 빼기도 합니다
  (8/10: 13시간 34분 근무에 90분 차감).
- 반차 인정분을 4시간으로 보는데, 서버는 실제로 더 후하게 정산합니다.
  8/14 오전반차는 `appcomeTm` 을 07:30 으로 당겨 `appworkTm=570` 을 인정했습니다.
  즉 여기 표시되는 값은 **보수적**이고, 배치 후 서버 값으로 교정됩니다.
- 세션이 만료되면 `gw.goorm.io`에서 다시 로그인해야 합니다.
- 휴가 신청은 초안까지만 만듭니다. **결재상신은 사용자가 결재 화면에서 직접** 누릅니다.
- 아이폰은 지원하지 않습니다. 익스텐션도 앱도 쓸 수 없고, 웹앱은 위 이유로 접었습니다.
