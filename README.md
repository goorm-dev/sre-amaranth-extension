# 구름 근무시간

아마란스(`gw.goorm.io`) 근태 API를 직접 호출해 **이번 달 남은 근무시간**을 계산합니다.
하루 8시간제 / 유연근무 최소 6시간 / 월 단위 정산 기준.

두 가지 형태로 제공합니다.

| | 위치 | 세션 |
|---|---|---|
| **Chrome 확장** | [manifest.json](manifest.json), [src/](src/) | 브라우저 쿠키를 읽음 |
| **Android 앱** | [app/](app/) — Capacitor | 앱에서 직접 로그인 |

계산 로직([lib/time.js](src/lib/time.js) · [holidays.js](src/lib/holidays.js) · [calc.js](src/lib/calc.js))은
플랫폼 의존성이 전혀 없어 **양쪽이 같은 파일을 공유**합니다 (`app/sync-lib.sh` 로 복사).

## 배포

- 확장: `./pack-extension.sh` → `amaranth-extension-vX.zip`
- 앱: `cd app && npx cap sync android && (cd android && ./gradlew assembleDebug)` → APK
- GitHub 릴리스에 두 산출물을 올리면, 확장이 [src/lib/updater.js](src/lib/updater.js) 로
  최신 태그와 버전을 비교해 **업데이트 알림**을 띄웁니다.


## 설치

1. `chrome://extensions` → 우측 상단 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램을 로드** → 이 폴더 선택
3. 툴바 아이콘 클릭

`gw.goorm.io`에 로그인만 되어 있으면 **어느 탭에서든** 동작합니다. 근태 페이지를 열어둘 필요가 없습니다.
근태 페이지에 들어가면 우측 하단에 같은 내용의 패널이 함께 뜹니다 — 근태신청서·결재처럼
`window.open()` 으로 열리는 **별도 팝업 창에는 뜨지 않습니다.**

## 계산 규칙

| 항목 | 정의 |
|---|---|
| 이번 달 인정근무 | `Σ appworkTm` — 마감된 날의 연차·반차 인정분은 서버가 이미 반영 |
| 휴가 인정 (예정) | 아직 집계 전인 오늘·미래 휴가. 반차 = 소정의 절반 |
| 월 소정근로 | **8시간 × 근무일수** |
| **남은 근무시간** | `월 소정근로 − (인정근무 + 휴가 인정)` |
| 남은 근무일 | 오늘 포함, 소정근로시간이 있고 **휴가로 다 덮이지 않은** 남은 날 |
| 하루 필요 | `(남은 근무시간 − 이미 정해진 날의 필요분) ÷ 나머지 근무일` |
| 어제까지 누적 | `Σ(인정근무 + 휴가 인정 − 8시간)` (마감된 날) |

### 하루 기준은 8시간 고정입니다

서버의 `selfCommuteStandardWorkTm` 은 **법정근로시간**이라 8시간보다 짧게 잡히는 날이 있습니다.
그 값을 기준으로 삼으면 실제로 채워야 하는 시간과 어긋나므로, 서버 값은 **"그날이 근무일인가"를
판별하는 데만** 쓰고 시간은 설정값(기본 8시간)으로 고정합니다.

### 필요 시간이 정해진 날은 평균에서 빼고 계산합니다

반차가 걸린 날은 그날 필요분(`8h − 4h = 4h`)이 이미 정해져 있습니다. 이걸 평균에 섞으면
8시간 아래로 끌려 내려가서, 정작 **평범한 날 몇 시간 일해야 하는지**를 알 수 없습니다.
그래서 반차 날과 계획을 넣은 날은 분자·분모에서 빼고 나머지 날로만 평균을 냅니다.

```
남은 125시간 32분, 남은 근무일 17일 (반차 2일 포함)

  섞어서 계산  → 125:32 ÷ 17 = 7시간 23분   ← 평범한 날 기준으로는 틀린 값
  반차 분리    → (125:32 − 8h) ÷ 15 = 7시간 50분   ✓
```

## 근무 계획

툴바 팝업에 달력이 **항상 펼쳐져** 있습니다. 남은 근무일을 눌러 그날 일할 시간을
정해두면, 나머지 날에 하루 몇 시간이 필요한지 즉시 다시 계산됩니다.

팝업 순서는 `남은 근무시간 → 오늘 출퇴근 → 월 집계 → 달력` 입니다.
오늘 정보를 보려고 달력 아래까지 스크롤할 일이 없도록 달력 위에 둡니다.

```
남은 144시간 / 18일

  계획 없음              → 하루 8시간
  9/3 하루만 6시간        → 하루 8시간 7분     (138h ÷ 17일)
  9/3~9/9 다섯 날 6시간   → 하루 8시간 46분    (114h ÷ 13일)
  남은 날 전부 6시간      → 계획 부족 36시간   (18일 × 6h = 108h)
```

달력의 색: 파란 테두리 = 계획, 하늘색 = 휴가, 회색 = 마감(실적), 주황 테두리 = 오늘.
**우측 상단 주황 점 = 휴게·외출 신청**이 있는 날입니다 — 필요 근무시간은 그대로고 퇴근만
밀리므로 값 대신 표식으로 알립니다 (셀에 마우스를 올리면 시간이 나옵니다).

마감된 날 칸에는 **월 집계와 같은 값**이 들어갑니다 — 미반영 휴게를 뺀 실질 인정근무에
휴가 크레딧을 더한 값입니다. 칸의 합이 `이번 달 인정근무` 와 정확히 일치합니다.

마감된 날과 휴일은 누를 수 없습니다. 계획은 브라우저에만 저장되고 그룹웨어로 전송되지 않습니다.

유연근무 하루 최소 6시간 기준으로 판정합니다.

- `남은 시간 ≤ 남은 일수 × 6h` → **매일 6시간이면 충족** (초록)
- `6h × 일수 < 남은 시간 ≤ 8h × 일수` → **매일 6시간으론 부족** (주황)
- `남은 시간 > 8h × 일수` → **8시간을 다 채워도 부족** (빨강)

오늘 출근했다면 **언제 퇴근하면 되는지**를 세 기준(최소 6h / 월 페이스 / 정량 8h)으로 보여줍니다.
`출근시각 + 근무시간 + 휴게시간`으로 계산하며, 경과 시간도 함께 표시합니다.

**휴가를 쓴 날은 유연근무 하한(6시간)이 적용되지 않습니다.** 그날 남은 소정근로가 곧 최소
근무시간입니다 — 오전반차(4시간 인정)면 최소도 정량도 `8h − 4h = 4h` 하나로 합쳐 보여줍니다.

**휴게시간은 하루에 한 번만 적용됩니다.** 오전반차 `09:00~14:00` 처럼 휴가 구간이 이미
휴게를 흡수했다면, 남은 근무에는 또 더하지 않습니다.

| 상황 | 출근 | 퇴근 |
|---|---|---|
| 오전반차 `09:00~14:00` | 14:39 | `14:39 + 4h` = **18:39** (휴게 추가 없음) |
| 오후반차 `14:00~18:00` | 09:00 | `09:00 + 1h + 4h` = **14:00** |
| 휴가 없음 | 10:00 | `10:00 + 1h + 8h` = **19:00** |
| 시간연차 `16:00~18:00` | 09:00 | `09:00 + 1h + 6h` = **16:00** |

### 검증

2026년 8월 실제 데이터로 대조했습니다.

```
8월 소정근로  160시간 (20일)
8월 인정근무  164시간 55분
8/31 제외 누적  +4시간 38분   ← 그룹웨어 화면의 "8월 누적 04시간 38분초과달성"과 일치
```

## API

네 엔드포인트를 씁니다.

### 1. 월 근태 조회

```
POST https://gw.goorm.io/personal/hpd0210/getWorkTimeList
  Authorization : Bearer <cookie.oAuthToken>
  transaction-id: 32자리 랜덤 hex
  timestamp     : Math.floor(Date.now()/1000)
  Access-Domain : https://gw.goorm.io
  menu-code     : HPD0210
  wehago-sign   : Base64( HmacSHA256(token + tid + timestamp + pathname, cookie.signKey) )
                  ※ pathname 만 서명한다 (쿼리스트링 제외)

  {"atDtList": ["20260901", "20260902", ...]}
```

- WEHAGO(더존 Amaranth 10) 플랫폼의 서명 요청 방식입니다. 구현은 [src/lib/gwapi.js](src/lib/gwapi.js).
- 토큰(`oAuthToken`)과 서명키(`signKey`)는 쿠키에 있습니다 (HttpOnly 아님).
- `coCd` / `empCd` 는 **보내지 않아도 됩니다** — 서버가 토큰에서 판별합니다.
- `atDtList` 에 원하는 날짜를 나열하면 되므로 **월 전체를 한 번에** 가져옵니다.

주요 응답 필드:

| 필드 | 의미 |
|---|---|
| `appworkTm` | 인정근무 (분). 반차·휴가 인정분 포함 |
| `selfCommuteStandardWorkTm` | 그날의 소정근로시간 (분). 휴일이면 0 |
| `exceptworkTm` | 제외근무 = 휴게시간 (보통 60) |
| `comeTm` / `leaveTm` | 실제 출퇴근 타각 (`HHMM`, 없으면 `----`) |
| `appcomeTm` / `appleaveTm` | 인정 출퇴근 |
| `attresultNm` | 정상근무 / 휴일 / 지각 / 부족 / 이상근태 |
| `atNm` | 오전반차 등 휴가 종류 |
| `worktmNm` | 승인 / 대기 |
| `holiYn` | 공휴일 여부 |
| `coCd` / `empCd` | 회사·사원 코드 (아래 실시간 조회에 필요) |

### 2. 근태신청(휴가) 조회

```
POST https://gw.goorm.io/personal/hpd0120/0hp00001
  menu-code: HPD0120
  {"startDt": "20260901", "endDt": "20260930", "flag": "2"}

  → resultData.atPopUpDetailInfos[].attendApplications[]
     { startDt, endDt, startTm, endTm, atItemNm: "연차휴가", atNm: "오전반차(보상)",
       approStateNm: "결재진행", ... }
```

- **`flag` 가 조회 기준을 정합니다** — `"1"` = 신청일, `"2"` = 사용일(휴가일).
  `flag=1` 로 9월을 조회하면 *9월에 신청한* 8월 휴가가 딸려 옵니다. **`flag=2` 를 씁니다.**
- `coCd` 는 생략 가능합니다.
- `결재진행`(승인 대기)도 포함하고, 반려·취소·취하 건은 제외합니다.
- 이름으로 종류를 가릅니다 — `휴게|외출` → 휴게, `휴가|연차|반차|…` → 휴가, 나머지(출장·시간외)는 다루지 않습니다.

**신청 구간에는 휴게시간이 포함돼 있습니다.** 오전반차는 점심을 물고 있어 구간이 5시간
(`09:00~14:00`)인데 오후반차는 4시간(`14:00~18:00`)입니다. 둘 다 실제 휴가는 4시간입니다.

그래서 **구간이 4시간을 넘으면 휴게 1시간을 뺍니다.**

| 신청 구간 | 길이 | 인정 |
|---|---|---|
| `07:30~12:30` 오전반차 | 5시간 | 4시간 |
| `14:00~18:00` 오후반차 | 4시간 | 4시간 |
| `09:00~18:00` 종일연차 | 9시간 | 8시간 |
| `16:00~18:00` 시간연차 | 2시간 | 2시간 |

`startTm`/`endTm` 이 없으면 `atNm` 이름으로 추정합니다 (반반차 = 1/4, 반차 = 1/2, 그 외 = 하루치).
하루에 오전반차 + 오후반차가 겹치면 합산하되 그날 소정근로를 넘지 않게 자릅니다.

### 휴게·외출 신청

같은 엔드포인트의 **`atPopupCd 51`** 그룹으로 함께 내려옵니다.

```
atPopupCd 51 / atItemNm "외출" / atNm "휴게" / 17:00~18:00 / 결재진행
```

**휴가와 방향이 반대입니다.**

| | 소정근로 | 인정근무 | 퇴근 시각 |
|---|---|---|---|
| 휴가(반차) | 줄어듦 (8h → 4h) | 크레딧으로 **더함** | 당겨짐 |
| 휴게·외출 | **그대로 8h** | 근로시간에서 **뺌** | **밀림** |

휴게시간은 근로시간에서 빠지므로 8시간을 채우려면 그만큼 더 있어야 합니다. 소정근로 의무가
줄어드는 게 아닙니다.

```
평소            10:00 출근 + 8h + 휴게 60분        → 19:00
휴게 60분 신청   10:00 출근 + 8h + 휴게 60분 + 60분 → 20:00
```

서버가 이미 반영했는지는 **`exceptworkTm` 이 기본 휴게(60분)보다 큰지**로 판단합니다.
결재진행 중이면 마감된 날이어도 서버가 빼지 않으므로, 그만큼을 인정근무에서 우리가 뺍니다.

```
9/1  09:00~20:38 (698분) − 인정 638분 = 60분 차감   exceptworkTm=60  ← 점심만, 휴게 미반영
     휴게 60분이 결재진행 → 인정근무를 638 → 578분으로 보정
```

### 회사 휴일

```
POST https://gw.goorm.io/human/common/getHolidayList
  menu-code: HPD0110
  {"year": "2026"}

  → [{ holiDt:"20260717", coCd:"1000", holiNm:"제헌절", holiYn:"Y" }, ...]
```

법정공휴일뿐 아니라 **회사 자체 휴무일**까지 들어 있어 내장 표보다 정확합니다.

```
20260717 제헌절       holiYn=Y   ← 법정공휴일이 아닌데 회사가 쉼
20260603 지방선거     holiYn=Y
20260312 창립기념일   holiYn=N   ← 달력에 등록만 된 기념일, 휴무 아님
```

`holiYn` 이 `"Y"` 인 것만 휴무로 봅니다. 실제 근태 데이터로 검증했습니다 — 지방선거·제헌절·
광복절·대체공휴일 모두 `attresultNm: "휴일"`, `selfCommuteStandardWorkTm: 0` 이었습니다.
`"N"` 은 근무일로 취급합니다. 실제로 쉬는 날이면 마감 후 서버 값으로 교정됩니다.

**제헌절 하나 때문에 2026년 7월 소정근로가 8시간 어긋났습니다.**

```
내장 표만   → 근무일 23일 / 176시간 + 8시간 = 184시간   ✗
서버 휴일   → 근무일 22일 / 176시간                     ✓
```

판정 우선순위는 **사용자 설정 > 서버 휴일 > 내장 표** 입니다. 서버가 그 해를 충분히
등록해 뒀으면(8건 이상) 내장 표는 아예 쓰지 않습니다 — 표에만 있는 날을 휴일로 잘못
잡는 걸 막기 위해서입니다. 2027년은 3건뿐이라 표로 폴백합니다.

휴일 목록은 연 단위로 `chrome.storage` 에 **7일간 캐시**합니다.

### 3. 오늘 실시간 타각

```
POST https://gw.goorm.io/human/common/judgeTimeManagement/getTodayComeLeaveInfo
  {"empCd": "...", "coCd": "...", "workDt": "20260901"}

  → {"resultCode":"SUCCESS", "comeTm":"202609011439", "leaveTm":"", "holidayYn":"N"}
```

- `menu-code` 헤더는 필요 없습니다.
- 이쪽은 **`empCd`/`coCd` 가 필수**입니다 (생략하면 `resultCode: "FAIL"`).
  월 근태 조회 응답 행에 둘 다 들어있으므로 거기서 뽑아 `chrome.storage` 에 캐시합니다.
  캐시가 비어 있으면 최근 45일을 훑어 확보합니다.
- 근태 배치를 기다리지 않고 **오늘 출근 시각이 즉시** 잡힙니다.

## 배치 지연과 하이브리드 추정

집계된 근태 데이터는 **다음날 새벽 5시 배치**로 채워집니다 (8/31 행의 `insertDt` = `2026-09-01 05:00:09 SYSTEM`).
그래서 오늘과 미래 날짜는 `selfCommuteStandardWorkTm` 이 `0`으로 옵니다.
(오늘 출퇴근 타각 자체는 위 실시간 엔드포인트로 바로 읽을 수 있습니다.)

진행 중인 달의 소정근로시간을 알 수 없으면 "남은 시간"을 계산할 수 없으므로 다음과 같이 처리합니다.

- **마감된 날** → 서버 값을 그대로 사용
- **오늘·미래** → **회사 휴일 목록**(아래)으로 근무일을 판별해 소정근로를 추정.
  서버 목록이 없거나 빈약하면 [src/lib/holidays.js](src/lib/holidays.js) 의 내장 표로 폴백

## 결재진행 중인 휴가

서버 배치는 **결재가 완료된** 휴가만 반영합니다. 결재진행 중이면 마감된 날이어도
반차가 빠진 순수 타각 시간만 들어옵니다.

```
9/1 오전반차(결재진행) → appworkTm 388분 (14:39~21:07)
   휴게 차감도, 반차 4시간 인정도 없이 타각 그대로.
   그대로 두면 누적이 388 − 480 = −1시간 32분 으로 찍힌다 (실제로는 +2시간 28분).
```

그래서 휴가 크레딧을 더할지는 "마감 여부"가 아니라 **서버가 그 휴가를 반영했는지**로
판단합니다 — 행의 `atNm` 에 휴가명이 찍혀 있으면 이미 반영된 것이므로 더하지 않습니다.
결재가 완료되면 서버 값으로 넘어가면서 같은 결과가 나옵니다 (이중 계상 없음).

추정한 날짜 수는 화면에 표시되고, 달이 진행되면서 서버 값으로 자동 교정됩니다.
회사 휴무일이 표와 다르면 팝업 **설정 → 추가 휴무일 / 휴일 해제**에서 조정하세요.

### 대체공휴일 규칙 (표를 고칠 때 확인)

| 대상 | 대체 조건 |
|---|---|
| 3·1절, 광복절, 개천절, 한글날, 부처님오신날, 성탄절 | 토·일 겹침 |
| 어린이날 | 토·일 또는 다른 공휴일 겹침 |
| 설날·추석 연휴 | 일요일 또는 다른 공휴일 겹침 — **토요일은 대체 없음** |
| 신정, 현충일 | 대체 없음 |

흔히 틀리는 두 가지입니다.

- 추석·설 연휴가 **토요일**과 겹쳐도 대체휴일은 생기지 않습니다.
  2026 추석은 9/24(목)~9/26(토)이고 **9/28(월)은 평일**입니다.
- **현충일**은 어느 요일에 걸려도 대체휴일이 없습니다.

## 휴가 신청

**앱·확장이 직접 상신하지 않습니다.** 진짜 신청서 화면을 띄우고 거기서 상신합니다.

| | |
|---|---|
| 확장 팝업 | **휴가 신청** → `#/HP/HPD0110/HPD0110` 로 이동 |
| 앱 | 상단 **＋** → 세션을 쿠키로 심고 근태신청서를 **앱 안에 임베드** |

앱은 **서버에 세션을 넘겨 쿠키를 받게** 합니다.

```
POST /gw/gw050A02 (form)  loginType=set-cookie&oAuthToken=…&signKey=…
  → Set-Cookie: oAuthToken, signKey, BIZCUBE_AT, BIZCUBE_HK, BIZCUBE_TYPE  (5개)
```

CapacitorHttp 가 네이티브로 요청하므로 이 쿠키는 **WebView 와 공유되는 네이티브
CookieManager** 에 저장됩니다. 그 뒤 WebView 를 `gw.goorm.io` 로 이동시키면
로그인된 상태로 열립니다. 뒤로가기로 앱에 돌아옵니다.

**iframe 은 쓰지 않습니다.** 앱 WebView 출처(localhost)와 교차 출처라 Android WebView 가
서드파티 쿠키를 막아 로그인이 풀린 채로 뜹니다. WebView 자체를 이동시키면 1st-party 라
쿠키가 정상 적용됩니다 (`server.allowNavigation` 으로 허용).

### 왜 API 로 직접 상신하지 않나

시도해봤고 대부분 재현했습니다 — `calculateApplicationDays`(계산) → `validateNew`(검증)
→ `0hr00011`(근태신청 저장) → `create`(결재문서 생성)까지 동작합니다. `create` 는
`approLineId` 를 비우면 서버가 기본 결재선을 붙여 주므로 결재선 문제도 없습니다.

그런데 `create` 로 만들어진 문서는 **`approState: "2"` 즉 미상신 초안**입니다.
결재선에 올리는 마지막 단계를 특정하지 못했습니다 (`/eap/eap096A45`, `/eap/eap096A48` 는
둘 다 결재양식 **조회**라 상신이 아닙니다).

절반만 재현하면 **초안만 쌓이고 상신은 안 되는** 상태가 되므로, 화면을 띄우는 쪽이
안전하고 결과도 확실합니다. 결재선·잔여연차·검증을 전부 아마란스가 처리합니다.

## 자동 갱신

화면에서 가장 빨리 낡는 값(경과 시간·퇴근 시각)은 `new Date()` 로 계산되므로 **서버와 무관**합니다.
반대로 월 집계는 다음날 새벽 배치라 낮에 아무리 불러도 값이 그대로입니다.
그래서 "N분마다 전부 다시 조회"는 **가장 낡는 값은 그대로 두고 서버만 두드리는** 방식이 됩니다.

둘로 나눴습니다.

| 무엇 | 주기 | 서버 호출 |
|---|---|---|
| 화면 다시 그리기 (경과 시간·퇴근 시각) | 30초 | **없음** |
| 오늘 타각 | 5분 — **퇴근이 찍히면 중단** | 1건 |
| 월 근태 + 휴가 | 부팅 시 1회 | 30일치 |

월 집계를 다시 부르는 경우는 세 가지뿐입니다 — **자정을 넘겼을 때**, **10분 넘게 자리를
비웠다 돌아왔을 때**, 그리고 수동 새로고침.

**탭이 보이지 않으면 아무것도 하지 않습니다** (`document.hidden`). 다른 탭에서 일하는 동안에는
폴링이 완전히 멈추고, 돌아오면 그때 판단합니다.

### 실패 처리

- **세션 만료**(401/403) → 자동 갱신을 **중단**하고 상태줄에 사유를 띄웁니다.
  만료된 세션으로 계속 두드려봐야 소용없기 때문입니다. 새로고침을 누르면 재개합니다.
- **그 외 오류** → 1 → 2 → 4 → 8 → 16 → 30분으로 백오프하고, 한 번 성공하면 초기화합니다.
  남은 대기 시간은 상태줄에 표시됩니다.

팝업은 열 때마다 새로 조회하므로 자동 재조회가 없습니다. 열어둔 동안 경과 시간이 낡지 않도록
30초마다 다시 그리기만 합니다.

## 근태 이상 (인정근무 0)

출근 타각이 빠지면 아마란스가 `attresultNm: "이상근태"` 로 분류하고 **인정근무를 0으로** 줍니다.
실제로 몇 시간을 일했든 상관없습니다.

```
20260812  이상근태  comeTm=----  leaveTm=2101  appworkTm=0  std=480
```

그대로 두면 그날 8시간이 통째로 부족분에 빨려 들어갑니다. 확장이 계산으로 메울 수 있는 값이
아니라(근태조정을 신청해야 채워집니다) **경고로 띄웁니다** — 해당 날짜와 타각 시각,
출퇴근 타각이 둘 다 있으면 못 받은 시간까지 함께 보여줍니다.

## 왜 휴가 신청은 안 만들었나

확장은 **전부 읽기 전용**입니다. 휴가 신청 기능은 의도적으로 넣지 않았습니다.

- 신청 API 를 알아내려면 **실제 신청서를 상신**해야 합니다. 결재자에게 알림이 가고
  되돌리려면 취소 절차를 밟아야 하는, 부작용이 되돌리기 어려운 캡처입니다.
- 신청서에는 결재선·사유·대결자 등 필드가 많고 검증이 서버와 화면에 흩어져 있어,
  일부만 흉내내면 **잘못된 문서가 결재에 올라갈** 위험이 있습니다.
- 지금은 읽기만 하므로 확장이 오작동해도 인사 데이터가 바뀌지 않습니다.
  쓰기가 들어가는 순간 그 보장이 사라집니다.

대신 **화면으로 이동하는 버튼**을 넣었습니다. 화면 코드는 메뉴 권한 조회(`/gw/gw999A12`)로
확인했습니다.

| 버튼 | 화면 | 경로 |
|---|---|---|
| 휴가 신청 | 근태신청서 | `#/HP/HPD0110/HPD0110` |
| 신청 현황 | 개인근태신청현황 | `#/HP/HPD0120/HPD0120` |
| 근무시간 | 개인근무시간현황 | `#/HP/HPD0210/HPD0210` |

팝업에서 누르면 이미 열려 있는 `gw.goorm.io` 탭을 재사용하고, 없으면 새 탭을 엽니다.
페이지 안 패널에서는 해시만 바꿔 같은 탭에서 이동합니다.

## 알려진 한계

- 진행 중인 달의 소정근로시간은 공휴일 표 기반 **추정**입니다 (위 참고).
- 내장 공휴일 표는 서버 목록이 빈약한 해에만 쓰이는 폴백입니다 (2025–2027년, 수작업).
  대체공휴일 규칙은 위 표를 참고하세요.
- 휴게시간은 60분 고정으로 계산합니다. 서버는 근무시간에 따라 더 빼기도 합니다
  (8/10: 13시간 34분 근무에 90분 차감).
- 반차 인정분을 4시간으로 보는데, 서버는 실제로 더 후하게 정산합니다.
  8/14 오전반차는 `appcomeTm` 을 07:30 으로 당겨 `appworkTm=570` 을 인정했습니다.
  즉 여기 표시되는 값은 **보수적**이고, 배치 후 서버 값으로 교정됩니다.
- 세션이 만료되면 `gw.goorm.io`에서 다시 로그인해야 합니다.
